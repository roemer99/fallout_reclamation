# Fallout Reclamation - Modding docs & verified EU5 facts

This folder is NOT loaded by the game. It is the reference for future work.

## Official script docs (EU5 1.4)

Put the files generated by the console command `script_docs` (start EU5 with
`-debug_mode`, open console, type `script_docs`) into this folder:

- `effects.log`        - every effect with scopes and usage
- `triggers.log`       - every trigger
- `event_targets.log`  - every link / event target (e.g. `capital`, `market`, `stockpile_in_market`)
- `modifiers.log`      - every modifier type (e.g. `global_<goods>_pop_demand`)
- `on_actions.log`     - every on_action, "From Code: Yes" = fired by the engine
- `event_scopes.log`, `custom_localization.log`

ALWAYS check these first before using a new effect/trigger/modifier.
Regenerate them after every game update.

## Verified facts (tested in this mod)

### Script
- Script values with more than 5 decimals are rejected ("Badly read script value").
- Constant script values (`x = 0.5`) cannot be used inside `change_variable`
  ("wrong type") -> write the number directly.
- A broken trigger can desync the parser for the REST of the file
  -> after changes, search debug.log for "Unexpected token".
- Avoid `?=` scopes inside effects; use `if = { limit = { exists = X } X = { ... } }`.
- Reading a location modifier via `capital.modifier:<name>` returned 0 -> use variables.
- `debug_log = "text"` writes to logs/debug.log (useful for diagnosis).

### Markets / goods
- Put goods into a market stockpile: `add_goods_supply = { goods = goods:<g> amount = <x> }` (market scope)
- Read stockpile: `capital.market.stockpile_in_market:<goods>` (link with data)
- Check: `goods_supply_in_market = { goods = <g> value > x }` (market scope)
- Market of a location: link `market`
- Per-goods pop demand: modifier `global_<goods>_pop_demand`
- Market storage capacity: location modifier `maximum_stockpile_capacity`
- Block foreign trade: country modifier `trade_isolation = yes`

### Localization
- Static modifiers: `STATIC_MODIFIER_NAME_<key>` / `STATIC_MODIFIER_DESC_<key>`
- Modifier types: `MODIFIER_TYPE_NAME_<key>` / `MODIFIER_TYPE_DESC_<key>`
- Map modes: `mapmode_<name>_name` + `MAPMODE_<NAME>`
- Government power name: key `legitimacy` (government_l_english)
- Override vanilla keys: `localization/english/replace/` (the "defined in multiple files" notice is only info)
- In GUI use `text = "KEY"` and put data functions into the loc string; `$KEY$` inside `raw_text` is NOT resolved.

### GUI
- Anchoring: `parentanchor` = point of the parent, `widgetanchor` = point of the widget itself.
  `parentanchor = right` alone puts the widget's LEFT edge on the parent's right edge (off screen);
  use `parentanchor = right|vcenter` + `widgetanchor = right|vcenter`.
- Texture paths do NOT evaluate data: `texture = "card_[X].dds"` is read literally.
  Show one of several images by stacking them with `visible` conditions instead.
- Root-level windows in NEW gui files are NOT created by the engine. The engine only
  instantiates widgets/types it knows by name. Host custom pop-ups in an existing root,
  e.g. `situation_view` (override of in_game/gui/situation_view.gui). NOTE: that root is only
  as wide as the situation panel, and the panel is drawn on top of it -> place pop-ups next
  to it: `parentanchor = right|vcenter` + `widgetanchor = left|vcenter`.
- Clicks only reach children INSIDE the parent's bounds. For a child outside them set
  `allow_outside = yes` on the parent; the child needs `alwaystransparent = no` +
  `filter_mouse = all` so clicks do not fall through to the map.
- Vanilla thin golden window frame: `background = { using = tile_frame_squared_texture
  using = color_new_gold modify_texture = { using = tile_frame_squared_bevel_texture alpha = 0.1 }
  using = overlay_window using = overlay_stone alpha = 0.9 }` (from template bg_lateralview).
- Scripted GUI in a button: `onclick = "[GetScriptedGui('key').Execute(GuiScope.SetRoot(GetPlayer.MakeScope).End)]"`,
  `enabled = "[GetScriptedGui('key').IsValid(GuiScope.SetRoot(GetPlayer.MakeScope).End)]"`
- Link with data in script values: `"capital.market.stockpile_in_market(goods:glass)"` (quoted, function style)
- Situations show as alert banners, NOT as a button above the map modes.
  The HRE-like button list comes from international organizations.
- Situation/disaster panels: `gui/panels/situation/<name>.gui`, `gui/panels/disaster/<name>.gui`
- Dropdown card: `situation_card_expandable` (gui/shared/cards.gui)
- Progress bar: `progressbar = { using = morale_progressbar_bar value = "[FixedPointToFloat(...)]" }` (0-100)
- Script value in GUI: `[GuiScope.SetRoot(GetPlayer.MakeScope).ScriptValue('name')|1]`
- Jump to a location: `onclick = "[ShowLocation(GetPlayer.GetCapital)]"`
- Static modifiers have no icon field: the first modifier type's icon is used
  (icons for modifier types: main_menu/common/modifier_icons).

### Content
- Disasters: do NOT use `map_mode = <custom map mode>` -> crash on load.
- Loading screens: the engine only knows the 11 vanilla scene names
  (loading_screen_scene_rossbach, ...); keep those names.
- `add_disease_outbreak` with `origin` in setup does not work in 1.4 -> use `spawn_disease`.
- Setup templates: `main_menu/setup/templates/<name>.txt`, used with `include = "<name>"`.
